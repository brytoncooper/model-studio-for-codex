# Model Deck contracts (B01)

Single source of truth for cross-process API vocabulary. JSON Schema files under this tree are authoritative; Swift and Python types are generated by `scripts/generate_contracts.py` and must not diverge as handwritten duplicates.

## Surfaces

| Prefix | Consumers |
|--------|-----------|
| `engine.v1.` | Application clients (Swift UI, CLI, MCP adapters) |
| `plugin.v1.` | Extension worker lifecycle on the private activation channel |
| `plugin.v1.broker.` | Supervisor-mediated capability calls from an activated worker |
| `plugin.v1.provider.` | External provider execution binding on the activation channel |

## Canonical packaging

- Author CLI namespace: **`model-deck`** (e.g. `model-deck plugin validate`).
- Plugin package manifest file name: **`manifest.json`** at the archive root.
- Wire transport: JSON-RPC 2.0 envelopes defined in `common/jsonrpc.schema.json`.


## `engine.v1.hello` handshake (B02 auth seam)

Local clients negotiate API version and optional required capabilities before authentication. There is no caller-supplied `role` field; the server assigns principal and grants after credential validation.

**Params (closed):**

- `client_name` (required)
- `offered_api` (required): shared `api_version` (`major` ≥ 1, `minor` ≥ 0)
- `required_capabilities` (optional): bounded feature id array; unknown or non-`supported` server knowledge rejects negotiation (`unsupported_capability`)
- `authentication` (optional): second-hello enrollment proof with `engine_instance_id` (UUID), `instance_nonce`, and `credential` (`instance_enrollment_credential` opaque secret — instance enrollment material, not a provider API token or `credential_ref`)

**Result:**

- `authenticated` (required bool)
- `api_profile` and `engine_instance_id` (required)
- `instance_nonce` (optional): rendezvous challenge on the unauthenticated first response; compare to the private rendezvous descriptor before sending `authentication`
- `capabilities` (optional): `engine_capability_features` snapshot (`features` tri-state map)

Handshake credentials and enrollment secrets must never appear in logs, diagnostics, or result payloads. Portable negotiation helpers live in `model_deck_contracts.negotiation` (API major/minor and required-capability checks aligned with `version_mismatch` / `unsupported_capability`).

## Model library listing (`engine.v1.models.list`)

- **`collection`**: `registered` (default) returns the engine model library inventory; `catalog` returns cache-only available provider models for a connection.
- **`connection_id`**: required when `collection=catalog`; optional filter when `collection=registered`.
- **`catalog.refresh`**: explicit job that may use the network; `models.list` with `collection=catalog` never implies network I/O.
- List items are a tagged union (`model_list_item`): `kind=registered` requires `registration_id`; `kind=catalog` forbids `registration_id`. **`provider_model_id` is not a registration identity.**


## Model library and connection revision (CAS)

Registered models carry a monotonic **`revision`** on `registered_model` and on `model_list_item` when `kind=registered`. Clients read revision from `models.list` (registered collection) or mutation results before calling write methods.

| Method | CAS input |
|--------|-----------|
| `models.register` | Required `expected_revision` (use `0` for initial registration admission per server policy) |
| `models.rename` | Required `expected_revision` matching the target registration |
| `models.remove` | Required `expected_revision` matching the target registration |
| `connections.save` | Required top-level `expected_revision`; `connection` uses `connection_save_input` **without** an embedded `revision` field (result `connection_ref` returns the new revision) |

Missing `expected_revision` on these writes is schema-invalid. Idempotency keys remain required where already specified.

## JSON Schema subset (validated at codegen)

Only constructs listed in `schema-subset.json` are permitted. Generation fails on unsupported keywords, `$ref` targets outside `contracts/`, or `additionalProperties: true` (literal permissive boolean).

Open JSON at operation boundaries uses the shared **`json_value`** definition in `common/types.schema.json` (recursive, bounded). Tool arguments, plugin operation inputs/outputs, and similar payloads reference `json_value` and are validated against registered operation schemas at dispatch—not by pretending they are empty closed objects.

Opaque references (`credential_ref`, `endpoint_config_ref`, `capability_snapshot_ref`, attachment handles) use **`opaque_ref`**: either a UUID or a `ref:` namespaced token. They must never carry secret material.

## Compatibility and validation policy

| Direction | Unknown fields |
|-----------|----------------|
| Mutation **requests** (params, manifest admission, broker calls) | **Rejected** — closed objects use `additionalProperties: false`; golden invalid fixtures assert this. |
| **Responses** and event notifications | **Forward-compatible decode** — clients ignore unknown optional fields on compatible API versions, per API.md negotiation rules. Schemas document the known field set; strict full-object validation is used for authored golden **encoding** fixtures, not to forbid forward-compatible decoding. |
| Plugin **manifest** at install/inspect | **Rejected** when unknown fields appear on closed manifest objects. |

Secret material must never appear in identity or reference-typed fields (`principal_id`, `invocation_id`, `registration_id`, `opaque_ref`, etc.).

## Platform ports (narrow, not wire RPC)

Schemas under `ports/` describe adapter contracts injected at composition time: `ApplicationPaths`, `InstanceLock`, `LocalTransport`, `OwnedProcessSupervisor`, `CredentialStore`, `AtomicFileWriter`, optional `WindowAttachment`. They are not JSON-RPC methods.

## Extensions

New public `engine.v1.*` methods or broker methods require lead approval and inventory update in `operations.inventory.json` before implementation.

## Capability tri-state vs authorization

`capability_tri_state` values are `supported`, `unsupported`, and `unknown` (capability knowledge). Authorization denial is returned as domain error `capability_denied`, not as a tri-state value. Golden fixtures assert `unknown` stays distinct from `unsupported`.

## B02 credential enrollment channel

Operator enrollment uses `enrollment_payload_handle` (UUID) on privileged save/replace params. The platform adapter reads the private enrollment channel bound to that handle and persists a `credential_ref` (`opaque_ref`). Plugins never receive enrollment payloads through attachments or broad-readable storage.
