# Local verification — version 2.1 — 2026-09-12

## Context compaction and Cursor Fast mode

- Codex 0.148 compacts long threads remotely: it appends a `compaction_trigger` item to a normal `/responses` turn (its current path) or posts the history to `/responses/compact` (its older path) and keeps exactly one returned `compaction` item. The router refused both for OpenRouter, custom endpoint and Cursor models, which ended every long thread on those models with "Error running remote compact task". The refusal is replaced by `context_compaction.py`: the router removes the trigger and the tools, appends Codex's own summarization prompt (copied from `codex-rs/prompts/templates/compact`), runs that turn on the same model, and answers with one compaction item whose `encrypted_content` is the summary under a router marker. Later turns turn that item into Codex's summary message for routed models, into a plain user message before OpenAI, and an OpenAI-made compaction item becomes an explicit "cannot be read here" note for routed models. Unary compaction answers JSON, including for errors.
- Streamed compaction keeps the connection alive with upstream comments and Cursor heartbeats while the summary is written; an empty or failed summary is reported as a failed compaction, never installed as history.
- Cursor Fast mode: Cursor's catalog exposes a per-model `fast` parameter (Composer 2/2.5, Grok 4.5/4.6, several GPT and Claude models; not Gemini Flash or Muse Spark). Cursor picker entries now offer Codex's Fast tier; `service_tier` reaches the SDK broker, which sends `fast=true` or `fast=false` explicitly and refuses Fast for a model without the parameter. The catalog is cached without the key in `cursor-models.json` (saved by every successful listing and by the router at launch, refreshed after 24 hours) so Fast is offered only where Cursor has it; the catalog ETag fingerprint includes that set so the picker reloads. Grok's reasoning parameter is named `effort` and is now matched (it was ignored before).
- Regression found and fixed while rebuilding: the stricter chat-wire translator (a terminal finish reason is required before a response completes) had not been carried into the Cursor adapter, so every Cursor turn in the uncommitted tree ended as `response.failed`. The adapter now feeds `tool_calls` at a tool boundary and `stop` at completion; tests cover both.
- Stale tests updated to the current wording and semantics (keyless billing text, explicit `strict` in chat tools, terminal-outcome requirement, reasoning item closed at end of stream). **246 Python tests pass** with the vendored tomlkit; local stand-ins only, no inference, no credentials. Live compaction on a real Cursor or OpenRouter thread has not been exercised yet; it is the first thing to watch after installing.
