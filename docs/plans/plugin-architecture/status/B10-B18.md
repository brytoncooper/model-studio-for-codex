## B15 — Continuation and compaction parity

**State: complete for the original provider/host parity milestone.**

- Written/source: [continuation guide and named compatibility matrix](../../../../python/src/model_deck/integrations/providers/continuation/README.md), private scoped SQLite store, engine-issued/persisted continuation scope, OpenAI-compatible raw-item restore, Codex bridge compaction/opaque-host conversion, and Cursor mechanism documentation.
- Ownership and isolation: the engine issues the session handle and captures route/configuration identity; the provider store binds session, connection/revision, provider, model, mode, endpoint ref, credential ref and handle. Bodies/workers cannot select scope. Session or route mismatches, missing/corrupt state and visible-history mismatches fail before HTTP. Completed responses save atomically; failed/incomplete/cancelled responses do not.
- Compaction: streamed trigger and unary endpoint use one tool-less same-route summary flow. Only a non-empty `run.completed` result is installed; partial failed output is discarded. The post-compaction summary is a host checkpoint, clears older provider-private state, and is never treated as portable encrypted continuation.
- Cursor: the actual pinned SDK path supports normalized full-history replay between turns and within-run callback suspension. Non-null native continuation remains explicitly refused because no portable SDK resume API is verified; no handle is fabricated.
- Evidence: 338 combined B15/provider/host/engine/Cursor/legacy tests passed. The integrated fixtures cross bridge, socket engine, provider, store, tool callback, compaction, a successful post-compaction turn, and an engine-authorized two-phase model reset that preserves the prior private binding until session persistence succeeds. Focused fixtures cover route/session refusal before endpoint or credential resolution, durable response ordering, reset rollback and crash adoption, legacy engine-database migration, reopen, corruption, failed summaries and unary compaction. Contracts (200 schemas) and architecture (208 files, zero findings) passed. No live provider request, installed-app mutation or live-state migration occurred.
- Remaining outside B15: generic public job-backed `engine.v1.sessions.compact` execution depends on the B19 job/history runner; the Codex compatibility endpoints return their compaction item directly. Live provider/cache qualification and a native Cursor resume mechanism remain unclaimed.
